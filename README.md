# ALPHA GRAVITY

**A 30-level neon 2D physics puzzle platformer — pure HTML5 Canvas + WebAudio, no engines, no art assets.**

Play in the browser, or install the Android build straight from [Releases](../../releases).

## What it is

Guide the Alpha Runner through 30 hand-authored neon sectors. Push crates onto pressure
plates, hold switches, ride moving platforms, bounce off launch pads and flip gravity
itself to walk on the ceiling. Everything the game draws and plays is generated at
runtime — the entire game is one self-contained `index.html`.

Stars are awarded per sector: finish (+1), collect every energy orb (+1), die zero
times (+1) — 90 stars in total. Progress is saved on the device.

## Play

| Platform | How |
| --- | --- |
| Browser (desktop, tablet, phone) | Open `index.html`, or the deployed preview URL. Installs to a home screen as a fullscreen PWA. |
| Android | Download `alpha-gravity-<version>.apk` from [Releases](../../releases) and install it (Android 8.0 / API 26 or newer). |

## Controls

| Action | Keyboard | Touch |
| --- | --- | --- |
| Move | `←` `→` or `A` `D` | on-screen ◀ ▶ pad |
| Jump | `SPACE`, `W`, or `↑` — hold to jump higher | ⤒ button |
| Restart sector | `R` | pause → ⟲ Restart |
| Pause | `ESC` or `P` | ❚❚ in the HUD |
| Fullscreen (browser) | `⛶` in the HUD | `⛶` in the HUD |
| Back (Android) | — | system back: pause → resume → sector map → menu |

Touch controls, their size, sound, music and haptics are all configurable in **Settings**.

## Responsive by design

- Layouts adapt from small phones in portrait to ultrawide desktops: safe-area aware
  padding (`env(safe-area-inset-*)`), dynamic viewport units, no pinch/double-tap zoom,
  and compact two-up menus in short landscape.
- The canvas re-measures on resize, orientation change, fullscreen change and mobile
  URL-bar movement, keeps a capped device-pixel-ratio for sharp rendering, and centres
  the sector when the viewport is larger than the level instead of leaving it stranded
  in a corner.
- Outside the sector a faint blueprint grid marks the play space, so tall and wide
  screens read as intentional rather than empty.

## Project layout

```
index.html                     the whole game (canvas rendering, physics, audio, UI)
icon.svg                       app / favicon / PWA / APK icon source art
manifest.webmanifest           web app manifest (fullscreen install)
android/                       Android wrapper project (Gradle, no AndroidX, no Kotlin)
  app/build.gradle             copies index.html into assets at build time, signing config
  app/src/main/java/...        MainActivity — fullscreen WebView shell + back-button bridge
  app/src/main/res/            theme, strings, adaptive launcher icon
.github/workflows/             tag → build APK → publish GitHub release
proguard-rules.pro             R8 keep rules used by the release build
```

The Android app contains **no copy of the game**: `syncWebApp` in
`android/app/build.gradle` copies `index.html`, `icon.svg` and `manifest.webmanifest`
from the repository root into the APK's assets, so the two builds can never drift.

## Build

### Web

There is no build step. Serve the repository root with any static file server and open
`index.html` — or just double-click the file.

### Android APK

Requirements: JDK 17 and an Android SDK with platform 34 + build-tools 34.

```bash
# debug build (debug key, installs on any device)
gradle -p android assembleDebug

# release build (R8 + the keep rules in proguard-rules.pro)
gradle -p android assembleRelease
```

Output: `android/app/build/outputs/apk/{debug,release}/`. If no release keystore is
configured the release APK is signed with the debug key, so it is still installable.

For a properly signed release build, pass a keystore — or let CI do it by setting the
`KEYSTORE_BASE64`, `KEYSTORE_PASSWORD`, `KEY_ALIAS` and `KEY_PASSWORD` repository secrets:

```bash
gradle -p android assembleRelease \
  -PalphaVersionName=1.0.0 -PalphaVersionCode=1 \
  -PalphaStoreFile=/path/to/release.jks \
  -PalphaStorePassword=… -PalphaKeyAlias=… -PalphaKeyPassword=…
```

## Releases

Pushing a tag starts the `Android APK` workflow, which builds the release APK, uploads
it as a workflow artifact and attaches it (plus `SHA256SUMS.txt`) to a GitHub release:

```bash
git tag v1.0.0
git push origin v1.0.0
```

The same workflow can be run manually from **Actions → Android APK → Run workflow**,
where you choose the version and whether to publish a release.
